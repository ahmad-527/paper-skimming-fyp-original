# Corrections to the historical report

The thesis file is published unchanged as the historical record. This file documents corrections to its descriptions and identifies unresolved questions; it does not alter the thesis, notebooks or their recorded outputs.

- **Token embeddings:** The thesis describes 300-dimensional GloVe embeddings. Model 1 uses a trainable 128-dimensional token embedding, while Models 2, 4 and 5 use the Universal Sentence Encoder. GloVe embeddings are not loaded or used in the implementation.
- **Character branches:** The thesis describes the character branches of Models 4 and 5 as Conv1D. Both use a bidirectional LSTM. Conv1D is used in the standalone character model, Model 3.
- **Model 5 fusion:** The thesis describes a bidirectional LSTM at the fusion stage. The implementation places that LSTM inside the character branch. Fusion uses concatenation and dense layers, including the line-number and total-lines feature branches.
- **Model 2 completion:** Model 2 is presented as completed in the thesis, but neither thesis-of-record notebook preserves a completed training/evaluation result for it. The 200k notebook preserves an XLA/GPU error involving string tensors. The 20k notebook has no saved training/evaluation output for Model 2, so its failure mechanism cannot be established from that copy. A later dev result of 71.26% accuracy and 0.7095 weighted F1 appears only in the January 2025 continuation.
- **200k abstract metrics:** The thesis abstract reports 85.2% accuracy and F1 "85.12". The results section and saved notebook dev output give 85.30% accuracy and 0.8512 weighted F1. The saved test result is 84.90% accuracy and 0.8471 weighted F1.
- **Hardware:** The thesis lists a local laptop with an RTX 3070 Ti. The notebooks use a Colab workflow, and the 200k notebook records a T4 GPU in its metadata. The 20k thesis-of-record and continuation notebooks preserve `nvidia-smi: command not found`; those copies do not independently establish T4 use.
- **Training exposure:** Neural-model fitting uses three epochs, `steps_per_epoch = int(0.1 * len(training_dataset))`, and no dataset shuffle. It is unresolved whether each epoch revisited the same initial approximately 10% of batches or advanced through the next slice. The archive does not state which occurred. The TF-IDF/Naive Bayes baseline fits all loaded training sentences.
- **Validation and F1:** Training-time validation is also restricted to 10% of dev batches. The reported model results instead use predictions over the full official dev or test split. F1 from `calculate_results` is the scikit-learn weighted average, not macro F1.
- **200k extraction and normalization:** The notebook points at `PubMed_200k_RCT_numbers_replaced_with_at_sign`, but its 7-Zip extraction commands are commented out and refer to the other split's `train.7z`. Its saved directory listing already contains `train.txt`, and its printed training preview includes numbers such as `90` instead of `@`. These facts leave the exact historical extraction/normalization procedure unresolved. A fresh-session clone alone does not reproduce the recorded setup.
- **Scope of the output:** The implemented models assign rhetorical-role labels to individual sentences; they do not generate summaries or jointly decode all sentence labels in an abstract. Positional features in Model 5 provide limited abstract context. The recorded single runs do not establish state-of-the-art performance, robustness or clinical utility.
- **Historical notebook prose:** Some explanatory Markdown retains reference-project values and 20k wording in the 200k notebook. The README tables use the saved result dictionaries rather than those prose comparisons. The archive has no fixed seeds or variance estimates, and runtime downloads are not pinned to historical revisions.
